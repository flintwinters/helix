# Helix

Think like a mathematician would.

Helix is an experimental Rust runtime with YAML source, immutable execution values, and readable YAML results and diagnostics. Programs are YAML representation graphs: singleton `$call`, `$ref` and `$literal` maps distinguish calls, lexical references and literal data. Quoting and mapping presentation order have no execution meaning; runtime maps use canonical string-key order. APIs, syntax and tooling should be discoverable by people and agents.

## Motivation

Make execution as readable and explicit as source. Prioritize structured, agent-consumable outputs and hierarchical discovery. Retaining a machine must preserve its meaning while another version advances. Ordinary data round-trips through YAML; function and machine inspection graphs do not promise executable disk restoration. Source/state edits are external changes, not requests to invalidate completed work; execution continues from the supplied valid state, and retained provenance does not certify externally edited values.

The ultimate application is declarative machine configuration through first-class types: resolve a machine description purely before applying effects (`CHARTER.md`). The type/class algebra, pure regions, constraints, state comparison and explicit host effects exist. A scoped Docker nginx workload exercises local/SSH reviewed application, fresh reconciliation and durable controller-death recovery; general declarative machine application and independently distributed reversibility remain future work. Keep the build bootstrap independent of Helix execution. Building a UI is out of scope; expose execution through APIs and CLI tooling.

Complexity must earn its place through concrete workloads. `CHARTER.md` section 12 governs feature admission and consolidation; roadmap entries alone do not justify expansion. Prefer completing a defining workload and reducing semantic interactions over adding surface or moving code merely to increase dogfooding.

## Architecture

- Project tooling defaults to concise, scoped text with actionable failures; complete versioned JSON is explicit. Optimize agent output for decision-relevant information and progressive discovery, not serialization alone. Completed text test results appear as suites finish; final policy aggregation can fail independently. Wrappers preserve language and pipeline wire contracts, including complete JSON reports.
- `src/model.rs` defines source graphs, dedicated runtime values and explicit execution state. Code, collections and machine versions share immutable storage with copy-on-write updates. Runtime functions and VMs are distinct from ordinary lists/maps. Annotation evidence is bounded ordinary data; live captures and continuations are summarized, never retained through that evidence.
- `src/graph.rs` preserves lexical topology and source spans; `src/graph/syntax.rs` is the authoritative syntax boundary over YAML representation nodes. Source analyses share exact-name-first lexical selection, keeping parameter members distinct from their base's contracts. Inspectable references are source-qualified paths with string-key and integer-index segments; arena indices and allocation addresses have no language meaning.
- `src/eval.rs` is the exhaustive outer dispatcher; `src/eval/` owns source evaluation, scopes, iteration and host interactions within the same iterative engine. Calls, annotations, error unwinding, memoization, cycle guards, resource budgets and phase state are explicit. Functions retain original code and lexical environments; execution never emits or reparses function source.
- `src/tooling/source.rs` reflects authoritative syntax, lexical bindings and bounded static evidence as ordinary data. Streaming search observes one source at a time; embedded `std:source` and `std:search` own query and structural-match policy. Unknown evidence remains explicit. Only the explicitly invoked probe stage runs candidates, in fresh confined machines without host dispatch.
- `src/tooling/analysis/` owns conservative non-executing diagnostics and canonical source formatting; its LSP uses the same diagnostics. Production library and tooling modules exercise these checks in the static suite; policy mutations verify field, literal, callback and missing-name feedback. Name checks reuse runtime lexical declarations and remain conservative about dynamic members. Annotation resolution and expanded inferred types are bounded; precision loss retains explicit unresolved obligations through shared type relations. Collection checks preserve empty-input callback skipping. Sibling interactive and inspection tooling reuse the linker and VM. CLI `check --evaluate` retains evaluation-based error collection; plain `check` never executes.
- `src/snapshot.rs` and `src/snapshot/` preserve complete bounded execution in a versioned object table with embedded source graphs and source-qualified paths. Version 2 records promises and bounded evaluated-value provenance; version 1 migrates explicitly. Named promise types compose registered obligations, and immutable mixins enforce reversible state bounds at admission and transitions. Promised machines refuse ordinary host dispatch, arbitrary effect resolution and independent-error checking; ordinary machines retain those APIs. `src/vm/peers.rs` composes promised participants with atomic peer rendezvous and bijective delivery receipts, checkpointing the entire system and its round-robin scheduler. Restoration validates complete participant histories; the guarantee does not extend to independently restored remote participants. Loading validates topology, references and continuations without opening imports or supplying host grants. Inspection and source recovery retain separate formats.
- `src/vm.rs` supplies immutable stepping, running, inspection and independent-error checking. Nested machines advance through an iterative scheduler, without recursively running another interpreter. Terminal stepping preserves state. VM checking collects reached evaluation failures in ordinary order without run preflight, preserving shared budgets and captured-input history; it does not statically analyze uncalled bodies.
- `src/builtins.rs` and `src/builtins/` own pure host operations and type/class validation. Public type constructors validate declarations through the shared parser before delegating assembly to embedded Helix modules; record replacement validates retained fields while discarding the replaced spec. Drift/convergence similarly delegate planning through ordinary calls in the same engine. The linker attaches required policy modules to the source graph. A single actor registry owns builtin identity, arity and evaluation policy. Literal subtype proofs cover numeric equality representations through bounded structural checks. Declarations validate defaults before candidate membership; structural subtype proofs remain separate. Refinements and whole-record constraints request predicates through the same engine; execution failures retain predicate blame and causes separately from rejection, and deterministic host traversals retain completed predicate answers. Host callbacks never execute Helix. A failing cleanup replaces the original outcome.
- Class realization enforces fixed values and whole-record constraints; adding a constraint invalidates realization. Class construction and type parsing share constraint-shape validation before any predicate execution. Proofs and inherited constraints use exact predicate source/capture identity; public value equality is not evidence of interchangeable predicates. Inheritance requires exact agreement among competing declarations and winning value representations; explicit values retain priority over equal defaults. Explicit provenance kinds distinguish fixed values from defaults independently of display labels; membership checks field schemas, explicitly fixed values and whole-record constraints. Drift/convergence compare configured values and preserve extra observed state, so an empty plan is not equivalent to closed-record membership.
- Explicit `type_time` regions have phase-local memoization and shared work/data budgets. Run preflight evaluates regions outside `try`/`vm` operands and function-body regions proven parameter-independent by a conservative source scan before the first run-time step (`src/eval/preflight.rs`); an outermost region records the pre-existing frame values it reads (`type_time_inputs`), preserving distinguishable ordinary-data representations while deduplicating exact repeats. Pure phases evaluate immutable linked file and embedded modules under the same rules; loading and import authorization precede execution. Determinism depends on the complete linked source and recorded inputs; caught errors retain phase information. Effect requests are rejected in pure phases before reaching a host.
- Effects yield explicit requests and retain completed outcomes in machine state. `src/vm/effects.rs` supplies caller-authorized host adapters, separate from immutable machines. External events interrupt and resume in-memory continuations; inspection is not disk restoration. Grants are host inputs, never authority carried by source or saved state. Opaque secret inputs resolve only in the host; their captured output and errors are suppressed before execution state or reconciliation persists them. Ordinary plaintext remains ordinary data. Executable grants are not an OS sandbox.
- Caller-owned durable journals lock one checkpoint path and flush before/after effect dispatch. Unacknowledged requests remain uncertain until explicit exact-request reconciliation; restored machines obtain fresh grants. Read-only recovery inspection validates the same journal without acquiring its writer lock or executing. A separate caller-selected target lock coordinates journals sharing one lock domain and preserves an uncertainty marker across controller death. This is not remote fencing, rollback or an exactly-once service.
- Local command lifecycle policy belongs to the caller-owned host: total time/output budgets, metadata progress, cancellation and explicitly classified retries share one request boundary. Unix process groups support cleanup, not containment or rollback; uncertain remote outcomes require explicit reconciliation through the durable journal.
- `src/link.rs` links and deduplicates literal imports before execution, preserving isolated module scopes and source identities. Confined loading authorizes canonical file roots supplied by the caller; source and recovery data cannot grant permissions. This is import confinement, not OS isolation.
- `src/value.rs`, `src/inspect.rs` and `src/emit.rs` own exact numeric comparison, cycle-aware structural function equality, stack-bounded retirement of retained execution graphs, source-aware object views and YAML/JSON boundaries. Execution inspection lives under `src/inspect/`, separate from dispatch. Ordinary data stays compact; function/machine results add named objects beside their value projection. Inspection does not execute the inspected machine.
- Pure failed-run recovery freezes completed ordinary-data fields and retries other fields from source. It does not restore active execution. Original source blame, navigable call chains, error causes and scalar values remain public contracts.
- `std/` supplies pure testing, configuration vocabulary, reflection, collection and data-only YAML libraries. `std:test` owns assertions, generators, selection, reports and golden-test decisions; `std:fuzz` owns robustness mutation generation. `tooling/test_policy.yaml` owns test-suite planning, failed-suite selection from validated saved reports and report aggregation. Public repository test-policy functions carry Helix input/result contracts. Python supplies captured process/file observations, independently validates policy consistency, mutation coverage and authority, vetoes golden success/blessing contradicted by captured observations, and detects interpreter failures; startup checks and build bootstrap remain independent of Helix. Parsing YAML data never reconstructs executable functions or machines.
- `std:facts` collects explicitly selected, typed Ubuntu 26.10 observations through existing local/SSH commands. Pure configuration consumes declared fact evidence; reviewed application recollects it before the provider lifecycle. Timestamps do not authorize application, and container qualification does not extend Debian providers or qualify normally booted services.
- `std:inventory` resolves static and caller-supplied dynamic host data into validated, explicit targets with connection provenance. Groups select hosts without configuration precedence; ordered overrides are explicit. Inventory describes connections, never grants authority or performs discovery.
- `std:orchestration` validates resource dependencies before invoking ordinary Helix callbacks. It reuses `std:dependency`, skips failed dependents, and coalesces change notifications into deferred handlers whose prerequisites succeeded. Effects remain in the existing engine; composition does not confer authority or imply rollback.
- `std:provider` owns the typed resource lifecycle: pure data plans, explicit ownership and removal, exact ordinary-data review matching before application (including numeric representations), and observation-based postconditions. Provider callbacks use the existing effect engine; metadata grants no authority. General package/file/service providers and concurrent-controller target locking remain separate work; durable dispatch uses the caller-owned journal.
- `std:command` adapts local command resources to that lifecycle with explicit observation guards and pure failure/change predicates. Its apply wrapper reports actual change after verification; commands carry no inferred idempotence or rollback guarantee.
- `tooling/usage_log.py` observes each runtime invocation through `manage.py`, and `tooling/usage_log.yaml` (a Helix program over `std:sqlite` run under `perform` with a write grant on the log directory) owns the `calls` table, additive migrations and insert in `runtime/usage.sqlite3`, including complete source, stdin programs, stdout and stderr; reporting stays read-only Python so it works without a build. Logging never affects the forwarded process, and direct binary calls are not covered.
- `src/vm/effects/ssh.rs` owns caller-granted remote command and UTF-8 file effects. Framed remote outcomes feed the shared command lifecycle; connection reuse is scoped to complete grants and fresh controller sessions. `std:ssh` observes prerequisites and verifies caller-declared bootstrap actions. Loopback and disposable-host suites qualify the documented subset; facts beyond the qualified Ubuntu scope and fleet support remain separate.
- `std:nginx` composes those existing provider and orchestration contracts for one typed container workload. Its configuration class reuses the input schema; one public boundary realizes defaults and constraints purely before effects, with ordinary-data provenance available for review. Helix owns desired-state policy; fixture helpers own package/file/process mechanisms. Fresh resource observations and HTTP activation gate success. Disposable Docker suites qualify local and caller-granted SSH application, including independently observed crash reconciliation and disk continuation. General service management, remote bootstrap and fleet coordination remain separate.
- Tests combine golden source/error contracts, ordinary-data fixpoints, dogfooded laws, public execution APIs, retained-state and pause checks, capability/resource boundaries, mutation sensitivity, and time/memory observations. Mutation execution preserves source-relative import context. `manage.py` is the authoritative tooling entrypoint; command discovery lives in `tooling/cli.py`, and `tooling/test_runner.py` owns explicit per-run test contexts. `LANGUAGE.md` owns core semantics, `LIBRARY.md` library contracts and `HOST.md` host-operation contracts; the static suite checks local manual navigation. Keep the main `README.md` concise: orientation, quickstart and links. Detailed operational and testing guidance belongs in focused manuals and `tests/README.md`.

## Current Big Tasks

Machine portability must distinguish captured execution state from future external
dependencies. `CHARTER.md` section 2 owns the agreed closed, explicitly bound and
open dependency boundaries; classification/enforcement and dependency inspection
remain future work. Shared immutable storage does not weaken snapshot closure,
but arbitrary commands prevent automatic environmental closure. Build on existing
source-independent restoration acceptance; derive claims from enforced capabilities,
never declarations alone.

Consolidation, declarative types, section 2's bounded reversible machines and section 7's current trust obligations are complete within their documented bounds. Versioned snapshots preserve bounded execution, and caller-owned effect journals preserve completed outcomes while refusing uncertain replay. The same nginx workload is now qualified locally and over SSH, including independently observed convergence and controller-death recovery. Choose the next milestone from a concrete remaining operational need; a real migration trial must declare its supported scope before provider expansion. Opaque secret inputs, read-only recovery inspection and persistent target locks now cover their bounded host contracts, and nginx realizes classes before application. External secret managers, facts beyond Ubuntu 26.10, remote fencing, fleet recovery and independently distributed reversible execution remain separate. Keep independent bootstrap and host validation; defer unrelated type algebra, provider breadth and policy migrations.

1. Measure and improve development feedback on actual production-policy workloads. Further dogfooding must demonstrate a concrete benefit while retaining independent bootstrap and host failure detection; moving more policy into Helix is not itself progress.
2. Extend reversible execution only with concrete workloads: independent remote transport and secret-bearing ordinary data remain unresolved. Monadic composition is the direction for independent reversible participants; its restoration protocol is unqualified, and current coordinated peer effects have a joint snapshot boundary.
3. Build declarative machine application on capability-controlled effects, using the scoped Ansible replacement roadmap in `CHARTER.md` section 11; qualify recovery and target coordination for each supported environment.
4. Maintain bounded evaluated-value source evidence and the explicit YAML representation model as syntax and tooling evolve; do not turn provenance into unbounded execution history.
